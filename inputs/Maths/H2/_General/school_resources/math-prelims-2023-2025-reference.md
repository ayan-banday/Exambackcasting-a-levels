### Diagram conventions (current standards 2023-2025)

1. **Argand diagrams** — origin O labelled, Re/Im axes, points labelled with capital letters (P, Q, R, A, B, C, W₁, W₂, etc.). When a complex number is plotted, both the point and the number label appear.
2. **Curve sketches** — must show: asymptotes (dashed lines), turning points (coordinates), axial intercepts (coordinates), and points specified in the question (P, Q, etc.). Axes labelled with y, x, and labelled O at origin.
3. **3D vector contexts** — diagrams use real-world models (canopy, gallery, prism, pyramid, room) with labelled points (A, B, C, ..., V, O) and unit vectors i, j, k specified relative to a reference plane.
4. **Statistics scatter diagrams** — labelled axes, all data points clearly marked, optionally with one point P labelled as "anomalous" for the student to omit before regression.
5. **Probability tree/Venn diagrams** — rarely drawn for the student; usually questions describe scenarios algebraically.
6. **Parametric curve sketches** — show direction of increase of parameter, key points, asymptotes if any.
7. **Periodic function diagrams** — show one full period plus extra for both sides, with markings for the period boundaries.

### Calibration rules for paper generation (TOP 5)

**Rule 1 — Topic balance per paper (memorize this):**
- P1: 12 questions averaging 8.3 marks each. Order roughly: opener inequalities/recurrence (4-5m) → functions/graphs (6-9m) → sigma/sequences (6-9m) → integration (8-10m) → DE (10-12m) → complex numbers (8-12m) → vectors (12-14m) → final real-world long question (12-15m).
- P2 Section A: 4 questions averaging 10m each. Always at least one Maclaurin and one vectors.
- P2 Section B: 6-8 questions. Always: P&C, discrete probability, discrete RV, binomial, normal, linear regression, hypothesis testing. Total 60m.

**Rule 2 — Mark allocation per topic (use these for question generation):**
- Show-that questions: 2-4 marks (1 mark per logical step)
- Sketch questions: 2-3 marks (1 for shape, 1 for asymptotes/turning points, 1 for intercepts)
- "Hence find" follow-ups: usually 1-3 marks each
- Multi-part complex numbers / vectors: 8-14 marks total
- Hypothesis testing: 4-6 marks for the test itself, +2 for assumptions/critical region/meaning
- Long DE: 6-10 marks for the full DE setup + solve + interpret
- Long linear regression: includes scatter (1m) + r-value (1m) + model choice + reliability + linear transform

**Rule 3 — Stem phrasing conventions:**
- Always use "Show that" when a downstream part depends on the result (gives the student the verification target).
- Always end variable graphs with: "stating the equations of any asymptotes, the coordinates of any stationary points, and the points where the graph crosses the axes."
- Always end DE questions with: "find the general/particular solution for y in terms of x" or "solve the differential equation."
- Always preface hypothesis testing with: "Test, at the X% significance level, whether..."
- Always preface stats with parameters: "In this question you should state the parameters of any distributions you use."
- Always end optimisation with: "(You need not show that your answer gives a maximum/minimum.)" when the context makes it obvious.
- Always end inequalities with "Hence ..." or "find the set of values of x..."
- Use "in the context of the question" for stats interpretation questions.

**Rule 4 — Diagram standards:**
- Always provide a labelled diagram (with O origin and named points) for 3D vector questions involving real-world models. Provide axes labelled with unit vectors i, j, k.
- Provide a labelled sketch for parametric/curve questions where the student is asked to sketch a transformed version.
- Provide Argand diagrams as a grid in the answer booklet with O marked; do NOT draw the points (the student plots them).
- For statistics scatter diagrams, do NOT pre-plot — student plots; provide grid only.
- For piecewise/periodic functions, the student sketches on a partially marked axis with the function definition stated.

**Rule 5 — Multi-part question depth norms:**
- Most questions have 3-5 sub-parts labelled (a), (b), (c), ... 
- Sub-parts often have (i), (ii), (iii) for further granularity.
- The final sub-part is almost always the highest mark — it requires synthesis across the prior parts.
- "Hence" parts are strict: the student must use the previous part. "Hence or otherwise" is permissive.
- Pure questions tend to be more linear (single solve path). Stats questions are more parallel (independent sub-parts).
- Every multi-part question of 8+ marks has at least one "Show that" step.
- Real-world dressed questions (the 12-15m closers) have 5-7 sub-parts and require switching between AP/GP/recurrence representations.

## Mark scheme conventions observed

From the 2024 HCI solutions and other solution PDFs sampled:

1. **Method marks (M) vs Accuracy marks (A)** — schemes award M1 for a correct method line (e.g. setting up an equation), and A1 for the correct final value/answer. Schemes often label M1, M1, A1 sequences.
2. **"Award follow-through"** — if a student makes one error but applies subsequent method correctly, the latter marks are awarded.
3. **Sketches require** — correct shape (M1), correct intercepts (A1), correct asymptotes (A1), correct turning points (A1) — sketches with 4 features score 4 marks.
4. **Show-that questions** — mark scheme typically requires explicit intermediate step. "Showing" requires correct algebra + clear logical flow.
5. **Hypothesis testing** — mark schemes specifically check: hypotheses stated correctly (with parameters defined), test statistic computed, p-value or critical value used, decision stated explicitly, conclusion in context.
6. **"In exact form"** — answers must be in fractions/surds/log expressions (not decimal). Decimal answers lose accuracy marks.
7. **Common errors flagged in schemes:**
   - Forgetting +C in indefinite integrals (ACC)
   - Incorrect rounding (3sf or 1dp) (ACC)
   - Notation errors (e.g. arg vs amplitude) (NOT)
   - Missing units in real-world questions (INSTR)
   - Forgetting to state parameters of distributions (INSTR)
